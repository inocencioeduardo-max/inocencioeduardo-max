# Maintaining this profile

Everything here is plain Node.js (22+) with **no dependencies**. Nothing calls an external stats-image service. All images are committed SVGs under `assets/`.

| File | What it is | How it changes |
| --- | --- | --- |
| `README.md` | Layout, intro, projects, links | Edit by hand |
| `profile.config.json` | Info-card text, portrait grid size | Edit, then `npm run build:static` |
| `data/portrait.txt` | ASCII portrait (the photo itself is never committed) | `scripts/build-portrait.mjs` |
| `assets/portrait.svg` | Self-typing ASCII portrait | Generated by `scripts/build-static.mjs` |
| `assets/card.svg` | Neofetch-style info card | Generated by `scripts/build-static.mjs` |
| `assets/contributions.svg` | Contribution heatmap + streak stats | Generated daily by the workflow |
| `data/contributions.json` | Last valid contribution snapshot | Generated daily by the workflow |

## Layout

The heatmap sits on top, with the portrait and card side by side in a `<table>` below it. A table is the only reliable way to put two images on one row on GitHub. Widths in `README.md` are chosen so the edges line up: GitHub adds 13px padding per cell side plus 1px borders, so 330 + 437 + 55 = 822, the heatmap's width. If you change one width, keep that sum. Portrait and card share a height (`ROW_H` in `scripts/lib/layout.mjs`).

On phones the two-column table scrolls sideways. All essential information is repeated as Markdown text below it.

## Editing text

- **Intro, projects, status labels, links:** edit `README.md`.
- **Info card:** edit `card.rows` in `profile.config.json`. Each row has a `key` and one or more `lines`. Text in `[brackets]` is shown dimmed, as a status tag. Keep lines under about 38 characters. The build fails with a clear message if the card overflows.

  ```sh
  npm run build:static    # regenerate portrait.svg + card.svg
  npm run validate        # check SVGs, alt text, local image paths
  npm run preview         # writes preview/index.html (desktop + phone)
  ```
- **Colours and timing:** the palette lives in `scripts/lib/svg.mjs`. Animation timings are in the `style` blocks of each generator.
- When you add links (LinkedIn, demos, a website), only add ones that resolve. Then run `npm run validate:links`.

## Portrait

`scripts/build-portrait.mjs` converts a PNG photo into `data/portrait.txt`. Keep the photo outside the repo.

```sh
node scripts/build-portrait.mjs ~/photo.png --crop 22,6,124,130 --gamma 1.1 --knockout 0.075 --sharpen 0.8
npm run build:static
```

These were the settings for the current portrait (a 150×150 source). A larger, evenly lit head-and-shoulders photo against a plain background gives more detail. Then drop `--crop`; the default is a centred crop. The options:

- `--knockout` blanks pixels close to the background tone.
- `--sharpen` brings back edges like glasses and eyes.
- `--gamma` above 1 thins out the glyphs.
- `--invert` suits light-background photos.

JPEG/HEIC must be converted to PNG first.

### Profile picture

`npm run build:avatar` writes `assets/avatar.svg`, a square, static head-and-shoulders crop of the same portrait. GitHub only accepts PNG/JPG/GIF profile pictures, so render it with Chrome and upload the PNG at github.com/settings/profile:

```sh
chrome --headless=new --hide-scrollbars --window-size=500,500 --screenshot=avatar.png assets/avatar.svg
```

## Contribution graph

`scripts/build-contributions.mjs` reads GitHub's public calendar at `https://github.com/users/<username>/contributions`, validates it and renders the SVG.

- **Never fabricated.** If the fetch fails, or the markup changes and validation fails (wrong day count, date gaps, missing counts, level/count disagreement), the script writes nothing. The last valid SVG and snapshot stay in place, and it logs a `::warning::`.
- `contributions.months` in `profile.config.json` sets the window: `6` shows the last 6 months with bigger squares, and `12` shows the full year. The snapshot always keeps the full year, so switching only needs `npm run build:offline`.
- `npm run build:offline` re-renders from `data/contributions.json` without the network. Use it after changing styles.
- The footer shows current/longest streak, best day and active days, all computed from the same daily counts. With no public activity it says so instead of showing zeros. It only shows **public** activity. To include private-repo activity as anonymous counts, turn on *Settings → Public profile → Contributions & activity → "Include private contributions on my profile"*. The next refresh picks it up.

## Workflows

- **`refresh-contributions.yml`** runs daily at 04:17 UTC and on demand (*Actions → Refresh contribution graph → Run workflow*). It has `contents: write` permission only for that job. It stages exactly `assets/contributions.svg` and `data/contributions.json`, and commits only when they changed. There is no `push` trigger, and pushes made with `GITHUB_TOKEN` don't start workflows, so it cannot loop.
- **`check.yml`** runs on pull requests with read-only permissions. It runs the tests, confirms the committed SVGs match the generators, and validates SVGs and README links.

GitHub pauses scheduled workflows in repositories with no activity for 60 days. If that happens, re-enable the workflow from the Actions tab.

## Tests

```sh
npm test                  # parser/renderer tests (synthetic fixtures only)
npm run validate          # SVG well-formedness, safety, accessibility; README images
npm run validate:links    # same, plus live checks of README links
```
